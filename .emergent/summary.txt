Original Problem Statement

The project went through a structured audit and hardening process to stabilize architecture and eliminate drift. The key objectives were:

Backend Unification & Refactor

Migrate signal logic from legacy status to a consistent state field.

Ensure backend (FastAPI + MongoDB) is the single source of truth.

Remove direct frontend Supabase usage for signals and move all CRUD through backend APIs.

Security Hardening

Remove Stripe/web payment surface entirely.

Disable insecure IAP webhook endpoints.

Fix critical Google IAP validation vulnerability (mock acceptance issue).

Tighten CORS configuration.

Remove hardcoded secrets.

Standardize backend API access.

Environment Drift Elimination

A working Expo environment existed separately (validated via EAS build).

The Expo configuration in frontend/ was outdated.

The working Expo environment (SDK 54, Router v6, Reanimated v4) was promoted upward.

frontend/app.json, frontend/eas.json, and frontend/package.json were replaced with the validated canonical configuration.

Supabase initialization was refactored to use app.json → extra instead of process.env.

The goal is now single-source configuration stability.
